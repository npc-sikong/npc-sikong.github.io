## 发现的差异／问题

- 同一账号，找回登录密码及更换密保显示第3题（初中班主任姓名），添加TRC20表单却显示第1题（学号）。只记录可见不一致，尚不能判断绑定校验实际使用哪个问题；不能据此复制错误数据到原型。
- 首次自动验证返回资金密码错误；用户接手后进入第二阶段，阻断已解除。未记录或推定用户实际输入的凭据。
- 更换密保第二阶段的问题选择默认显示第1题，而原问题为第3题；列表包含第1题学号、第3题初中班主任、第2题小学班主任。这是新问题选择列表，不等同于原密保已被更换。
- 用户保存成第1题后，找回密码、再次更换密保及添加TRC20均显示第1题；这只能确认本次状态一致，不能排除添加TRC20此前把第3题错显示为第1题的问题。
- 测试服实际允许密保提示与答案相同；“提示不能与答案相同”仍是本项目提出、测试服未实现的新增校验要求。
- 已登录状态进入登录地址会返回用户中心；不能将同浏览器新标签当成独立未登录会话。

## 后续若恢复全量实测的条件

1. 当前未绑谷歌账号：已完成所有可达安全表单核对、客服跳转、密保更换成功和问题同步；待用户提交登录密码更换／找回、资金密码更换、密保提示留空。
2. 谷歌完整生命周期：确认正确资金密码后进入生成密钥阶段；用户完成初次绑定并自行保存恢复码。再核对已绑谷歌的改密、密保和地址表单；用户操作正常更换、正常解绑、恢复码授权、恢复重新绑定、恢复解绑，逐项验证结果及恢复码是否失效。不保存真实密钥或恢复码。
3. 独立第二会话：需另一浏览器已有登录，才可检查密码找回／谷歌更换后旧会话注销。同浏览器共享会话不能替代此测试。
4. 绑定提现地址：需用户提供或手动绑定专用测试TRC20地址；随后验证按地址返回账号。没有地址时不编造地址或绑定第三方地址。
5. 首次设置分支：需用户创建新测试账号，核对无资金密码无密保时的首次组合设置，以及先单独设置资金密码再设置密保的历史分支。现有已设置账号不能假装初始账号。
6. 原有/新增定稿：只有测试服入口与成功流程有证据的按对应范围确认；被账号状态、配置或手动提交阻断的标“待核验”，不因为暂不可测改标“新增”。
